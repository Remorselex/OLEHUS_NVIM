# Neovim + LazyVim — шпаргалка

Лидер — `Space`. Нажми `Space` и подожди: `which-key` покажет всё меню.
Эта шпаргалка открывается командой `helpmevim` из любого места.

# 1. Старт и обучение

- `:Tutor` — интерактивный курс Vim (⚠️ **с большой T**). Из шелла: `vimtutor`

# 2. Основы Vim

### Выживание

| клавиши | действие |
|---|---|
| `i` / `Esc` | вставка / обратно в normal |
| `Ctrl+S` или `:w` | сохранить (работает и из insert) |
| `:wa` · `ZZ` · `:q` · `:qa` | сохранить всё · сохранить+закрыть окно · закрыть окно · выйти |
| `u` / `Ctrl+r` / `.` | отмена / повтор отмены / повторить последнее действие |

### Правка

| клавиши | действие |
|---|---|
| `dd` `yy` `p` | вырезать строку · копировать · вставить |
| `ciw` `ci(` `ci"` | изменить слово · внутри скобок · внутри кавычек |
| `v` `V` `Ctrl+v` | выделение: символ · строка · блок |
| `>7j` | сдвинуть отступ у 7 строк вниз |

### Автоформат при сохранении

На `:w` срабатывает `clang-format` (C++) / `prettier` (ts/tsx). Если файл «сам переформатировался» — это оно.
Выключить: `Space u f` (буфер) · `Space u F` (глобально).

# 3. Навигация

**Правило:** `j`/`k` — только на соседние строки. Дальше — прыжками.

### Мотать по файлу

| клавиши | действие |
|---|---|
| **`Ctrl+D` / `Ctrl+U`** | **полэкрана вниз / вверх** — основной способ |
| `Ctrl+F` / `Ctrl+B` | страница вниз / вверх |
| `gg` / `G` / `42G` | начало · конец файла · к строке 42 |
| `H` / `M` / `L` | верх · середина · низ видимого экрана |
| `zz` / `zt` / `zb` | текущую строку в центр · верх · низ экрана |
| `{` / `}` | предыдущий / следующий блок кода |
| `%` | к парной скобке |
| `[[` / `]]` | к предыдущей / следующей функции |
| `Ctrl+O` / `Ctrl+I` | **назад / вперёд по прыжкам** (Back/Forward как в IDE) |

### Прыжок в любую точку экрана

`s` + 2 символа — подсвечиваются метки, жмёшь метку и ты там (flash.nvim). Быстрее любого скролла.
`S` — выбрать узел кода (treesitter).

### Внутри строки

| клавиши | действие |
|---|---|
| `w` `b` `e` | по словам вперёд · назад · конец слова |
| `0` `^` `$` | начало · первый непробельный · конец строки |
| `f<символ>` / `t<символ>` | к символу / перед символом |
| `;` / `,` | повторить последний `f`/`t` вперёд / назад |

### Относительная нумерация

Слева не абсолютные номера, а **расстояние от курсора** — это прицел:

| клавиши | действие |
|---|---|
| `5j` / `12k` | вниз на 5 / вверх на 12 — число берёшь из колонки |
| `d5j` / `y3k` | удалить 5 строк вниз / скопировать 3 вверх |
| `Space u L` / `Space u l` | вкл-выкл относительную нумерацию / номера вообще |

### Между файлами

| способ | клавиши | когда быстрее |
|---|---|---|
| Fuzzy по имени/пути | `Space Space` | знаешь имя: `bannercard` → Enter; работает и по пути |
| **Navigation bar** (как `Cmd+↑`) | `Space ;` | помнишь *где* лежит: крошки → пивот → меню → стрелки → Enter |
| Дерево файлов | `Space e` | нужен обзор; `/` внутри фильтрует |
| Открытые файлы | `Space ,` | вернуться к буферу |
| Туда-обратно | `Ctrl+^` | метаться между двумя файлами |
| Соседний буфер | `Shift+H` / `Shift+L` | листать по порядку |

### Буферы, окна, вкладки — три разные вещи

- **Буфер** — открытый файл в памяти; полоса сверху = буферы
- **Окно** (split) — вид на буфер; `:q` закрывает **окно**, а не файл
- **Вкладка Vim** — набор окон; это не полоса сверху и не вкладки Ghostty

| клавиши | действие |
|---|---|
| `Space b d` | закрыть буфер (окно остаётся) |
| `Space b o` | закрыть все **остальные** буферы |
| `Space b p` / `Space b P` | закрепить / закрыть незакреплённые |

### Поиск по проекту

| клавиши | действие |
|---|---|
| `Space /` | grep по проекту (живой) |
| `Space s w` | grep слова под курсором |
| `Space s b` | поиск по строкам буфера |
| `Ctrl+q` в пикере | результаты → quickfix, листать `]q` / `[q` |
| `Ctrl+v` / `Ctrl+s` | открыть результат в сплите |

Требует `ripgrep`. Без него пикеры молча дают `0/0` и «Failed to spawn rg».

**Функцию ищут не грепом, а символами:** `Space s S` (по проекту) · `Space s s` (в файле).

# 5. Git

### Постоянная панель (главная схема, аналог Git в IDEA)

lazygit — внешний процесс: если он дочерний для nvim, закрытие окна убивает его и следующий запуск сканит всё заново. Поэтому держим его **отдельным долгоживущим процессом**:

1. редактор запускать через `v` (слушает сокет `/tmp/nvim.sock`):

```bash
v .
```

2. сплит под git — `Cmd+D` (вправо) или `Cmd+Shift+D` (вниз), в нём:

```bash
lg
```

3. переключение панелей — `Cmd+Alt+←/→`, процессы не трогаются
4. в lazygit `e` на файле → файл открывается **в соседнем nvim**, lazygit сохраняет состояние

`Space g g` внутри nvim остаётся для разовых заглядываний.

### Патчи

Из шелла больше не нужно. Две разные вещи:

**Патч как операция** — собрать из произвольных строк любых коммитов и переложить. Это lazygit, `Ctrl+P` на выделенных строках в файле коммита:

| | |
|---|---|
| `c` | сбросить собранный патч |
| `a` | применить |
| `r` | применить в обратную сторону |
| `y` | скопировать патч в буфер обмена |

Набор пунктов зависит от контекста: на коммите не-HEAD добавляются перенос патча в другой коммит и в индекс.

**Патч как файл** — `format-patch` / `am`; в Neogit это не портировали, поэтому сделано своим модулем `lua/util/git-patch.lua`. Файлы кладутся в `~/patches/`, путь сразу попадает в буфер обмена.

| клавиши | что |
|---|---|
| `Space g m w` | все незакоммиченные изменения → патч |
| `Space g m s` | только застейдженное → патч |
| `Space g m f` | текущий файл → патч |
| `Space g m c` | выбрать коммит → `format-patch -1` (формат для `git am`) |
| `Space g m a` | выбрать файл из `~/patches` и применить |

Применение идёт через `git apply --check`: если патч не ложится, рабочее дерево не трогается вообще.

### Worktree: ветки не переключают, а ходят по каталогам

Главное правило git: **одна ветка может быть выкинута только в одном worktree**. Поэтому «не могу прыгнуть на master» — это не баг lazygit, а инвариант git:

```
fatal: 'master' is already used by worktree at '/Users/user/IdeaProjects/monoNew-wktr2'
```

master уже открыт в соседнем каталоге. В worktree-модели на него не переключаются — в него **переходят**.

| команда | что делает |
|---|---|
| `wt` | fzf-список всех worktree → переход в выбранный |
| `wt master` | переход в worktree, чей путь или ветка содержит подстроку |
| `wt-add <ветка>` | создать worktree рядом с основным деревом, каталог назвать по ветке |
| `wt-rm` | выбрать worktree и удалить |
| `git worktree list` | плоский список: путь → ветка |

В промпте линкованный worktree помечается **`wt:<имя>`** перед веткой (в основном дереве метки нет) — видно, где ты, без единой команды.

Каталоги называй по ветке (`monoNew-master`), а не `wktr2` — через неделю не вспомнить, что где.

В lazygit worktree живут вкладкой в панели файлов: `1`, затем `]` / `[` для переключения вкладок, `w` — создать новый. Остальные клавиши панели — по `?`.
В Neogit — попап `w`.

### difftastic — структурный дифф

Сравнивает деревья разбора, а не строки: переносы, переформатирование и переезд кода не показываются как изменение.

```
git diff  →  4 insertions(+), 1 deletion(-)
git dft   →  No syntactic changes.
```

| команда | что |
|---|---|
| `git dft [путь]` | структурный дифф рабочей копии или коммита |
| `git dlog` | лог с структурными диффами |
| `git dshow <коммит>` | показать коммит структурно |

Дефолтный `git diff` не тронут — delta остаётся везде, включая lazygit и diffview. difftastic вызывается только этими тремя алиасами: структурный дифф медленнее и не умеет в подсветку слов внутри строки, так что как ежедневный он хуже.

### Neogit — порт Magit (самый близкий аналог VCS в IDEA)

`Space g n` — буфер статуса, из него делается всё. Это обычный буфер nvim: навигация как в коде, `q` закрывает, состояние не теряется.

| в статусе | действие |
|---|---|
| `<tab>` | свернуть/развернуть секцию, `1`…`4` — глубина всего дерева |
| `<cr>` | **открыть файл на правку прямо отсюда**, `<s-cr>` — подглядеть |
| `s` / `u` | застейджить / снять — файл, ханк или выделенные строки |
| `x` | откатить изменение (файл/ханк/строки) |
| `-` | инвертировать ханк |
| `<c-v>` `<c-x>` `<c-t>` | открыть файл в вертикали / горизонтали / вкладке |

Дальше — попапы: жмёшь букву, видишь меню с флагами, выбираешь. Флаги залипают между вызовами.

| клавиша | попап | что внутри |
|---|---|---|
| `c` | Commit | `c` коммит, `a` amend, `w` reword, `f` fixup, `s` squash, `F`/`S` мгновенные fixup/squash, **`x` absorb** |
| `l` | Log | по текущей ветке, HEAD, всем веткам, всем рефам, с фильтрами |
| `A` | Cherry-pick | `A` pick, `a` apply (без коммита), `h` harvest, `m` squash, `d` donate, `n` spinout, `s` spinoff |
| `v` | Revert | откатить конкретный коммит коммитом-обраткой |
| `r` | Rebase | `i` интерактивно, **`m` изменить коммит в истории**, **`w` переписать сообщение**, **`d` удалить коммит**, `f` autosquash, `s` подмножество |
| `X` | Reset | `f` файл, `b` ветка, `s` soft, `m` mixed, `h` hard, `k` keep, `i` только индекс, `w` только рабочая копия |
| `Z` | Stash | `z` всё, `i` только индекс, `w` только рабочая копия, `x` с сохранением индекса, `p`/`a`/`d` pop/apply/drop |
| `d` | Diff | открывается в diffview |
| `b` `t` `m` `p` `P` `f` `M` `w` `B` `i` | branch, tag, merge, pull, push, fetch, remote, worktree, bisect, ignore |
| `?` | справка по всем клавишам текущего буфера |

`Space g N` — сразу лог коммитов. На коммите в логе те же попапы: `A` черипикнуть его, `v` реверт, `X f` откатить один файл к его состоянию.

**Сообщение коммита пишется в обычном буфере** — со спеллчеком, undo, LSP и твоими биндами. `:wq` коммитит, `:q!` отменяет.

`c x` (absorb) — раскидывает текущие правки fixup-коммитами по тем коммитам, которые эти строки ввели, и автоматически делает autosquash. Требует бинарь `git-absorb` (стоит).

### lazygit: базовые клавиши

| клавиша | действие |
|---|---|
| `space` / `a` | стейдж файла / всех |
| `Enter` на файле | вид по кускам (hunk): `space` стейдж, `d` выбросить, `v` диапазон |
| `c` | коммит · `A` влить застейдженное в выбранный коммит |
| `b` | ветки · `f` fetch · `s` stash |
| `+` | развернуть панель на весь экран |
| `z` | **undo** последней операции (через reflog) |
| `?` | справка по текущей панели |

### Ребейз, черипик, конфликты

| клавиша | действие |
|---|---|
| `e` в логе | начать интерактивный ребейз с коммита |
| `s` / `f` / `r` / `d` | squash · fixup · reword · drop |
| `Ctrl+J` / `Ctrl+K` | переставить коммит вниз / вверх |
| `Shift+C` / `Shift+V` | скопировать коммит(ы) / применить (cherry-pick) |
| конфликт | зайти в файл → выбрать сторону, `e` — открыть в nvim; `c` continue, `a` abort |

### Откат файла

| задача | как |
|---|---|
| выбросить все правки файла | Files → `d` → «discard all changes» |
| выбросить только незастейдженное | Files → `d` → «discard unstaged» |
| откатить один кусок | `Enter` на файле → hunk → `d` |
| вернуть файл из старого коммита | Commits → коммит → `Enter` → файл → `c` |
| меню ресетов (hard/soft/upstream) | `D` |

⚠️ Discard незакоммиченного **необратим** — reflog не спасёт. Сомневаешься → сначала `s` (stash).

### Стеш и патчи (lazygit)

**Стешнуть один файл** (прямой команды нет — через стейдж):
1. `space` на нужном файле в Files (застейджить только его)
2. `S` → «stash staged changes»

Так же работает для части файла: `Enter` → `space` на кусках → `S`.

| клавиша | действие |
|---|---|
| `s` | стешнуть всё |
| `S` | меню: all / staged / unstaged / keep index |
| `g` / `r` в панели Stash | вернуть (pop) / переименовать |

Из шелла: `git stash push -- path/to/file`

**Custom patch** (`Ctrl+P`) — перенос изменений между коммитами:
Commits → `Enter` на коммите → `space` на файле (весь) или `Enter`+`space` на кусках (часть) → `Ctrl+P` → apply / move to commit / remove from commit / pull out into new commit / copy to clipboard.

**Патч-файлом для отправки** — быстрее из шелла:

| задача | команда |
|---|---|
| один файл | `git diff -- path > one.patch` |
| всё незастейдженное | `git diff > all.patch` |
| всё вместе со стейджем | `git diff HEAD > all.patch` |
| только стейдж | `git diff --cached > staged.patch` |
| коммит | `git format-patch -1 <sha>` |
| применить | `git apply all.patch` |

В lazygit `Ctrl+O` копирует дифф в буфер, `y` в Files — путь файла.

### Диффы

Настроен **delta**: подсветка синтаксиса + пословная зелёно-красная подсветка внутри строки (в lazygit и в `git diff`/`show`/`log -p`).

| где | как |
|---|---|
| `n` / `N` в диффе | прыжки между изменёнными участками |
| `Space g v d` | diffview: полноэкранный дифф + дерево изменённых файлов |
| `Space g v f` / `g v r` | история файла / история репы |
| конфликт в diffview | три панели: ours / theirs / результат |

### Инлайн в буфере (gitsigns)

| клавиши | действие |
|---|---|
| `]h` / `[h` | следующий / предыдущий изменённый кусок |
| `Space g h s` / `g h p` / `g h r` | застейджить кусок · превью «как было» · откатить кусок |
| `Space g v h` / `g v w` / `g v x` | подсветка изменённых строк · пословная · показать удалённые |

### Blame

| клавиши | что |
|---|---|
| `Space g b` | автор, дата, коммит для строки под курсором |
| `Space g v b` | постоянная inline-аннотация (как Annotate в IDEA) |
| `:Gitsigns blame` | панель blame для всего файла |

### Переключение окон и фокус

| клавиши | действие |
|---|---|
| `Ctrl+H` / `J` / `K` / `L` | перейти в окно влево / вниз / вверх / вправо |
| **`Ctrl+W` `w`** | цикл по **всем** окнам, включая плавающие — спасалка, когда фокус «потерялся» |
| `Ctrl+W` `p` | вернуться в предыдущее окно |
| `Ctrl+W` `o` | закрыть все окна, кроме текущего |
| `Space w d` | закрыть текущее окно |

Плавающие окна живут отдельно — `Ctrl+H/L` из них не работает, у каждого своя клавиша выхода:

| окно | как вернуть фокус |
|---|---|
| терминал (`Ctrl+/`) | `Ctrl+/` — спрятать (тот же хоткей) |
| lazygit (`Space g g`) | `q` |
| пикер (`Space Space`, `Space /`) | `Esc` закрыть · `/` фокус ввод↔список · `Alt+W` цикл ввод→список→превью |
| Explorer (`Space e`) | `Ctrl+L` уйти в редактор · `Space e` свернуть |
| диагностика (`Space x X`) | `q` |

Мышь не нужна никогда: всплывашка закрывается своей клавишей, между обычными окнами — `Ctrl+H/J/K/L`, а `Ctrl+W w` вытащит из любого состояния.

# 6. Терминал и запуск

### Терминал

| клавиши | действие |
|---|---|
| `Ctrl+/` | открыть / свернуть плавающий терминал (процесс продолжает работать) |
| `i` / `a` | войти в terminal mode (печатать) |
| `Ctrl+C` | **остановить** процесс (dev-server) |
| `Esc` `Esc` **быстро** | выйти в normal mode (окно **200 мс**! медленный двойной Esc уходит в процесс) |
| `q` | спрятать окно — только из normal mode |
| `exit` / `Ctrl+D` | закрыть терминал совсем |

`Ctrl+/` только **прячет** терминал — dev-server продолжает крутиться. Остановить — сначала `Ctrl+C` внутри.

Самый надёжный способ закрыть: **`Ctrl+/`** — работает прямо из terminal mode (тот же хоткей и открывает, и прячет). `q` и `Esc` в terminal mode уходят процессу, а не nvim.

### npm-скрипты (кнопка ▶)

|---|---|
| `Space r r` | список скриптов **пакета под курсором** → Enter |
| `Space r l` | повторить последний скрипт |
| `nr` / `nr -` | то же из шелла (сам определяет npm/yarn/pnpm по локфайлу) |
| `ni` / `ni <pkg>` / `nlx <pkg>` | install · добавить пакет · разовый запуск (как npx) |

### Сборка C++ и дебаг

```bash
cmake -S . -B build -G Ninja -DCMAKE_EXPORT_COMPILE_COMMANDS=ON && cmake --build build
```

| клавиши | действие |
|---|---|
| `Space d B` | breakpoint |
| `Space d c` / `d o` / `d i` | запустить/продолжить · step over · step into |
| `Space d u` | панель дебага (переменные, стек) |

# 7. Окружение проектов

### C++ — без этого clangd слепой

clangd понимает проект только через `compile_commands.json`:

```bash
cmake -S . -B build -DCMAKE_EXPORT_COMPILE_COMMANDS=ON && ln -sf build/compile_commands.json .
```

В CLion-проектах база уже есть в `cmake-build-debug/` — достаточно симлинка в корень CMake-проекта, CLion её сам обновляет при reload.

### TypeScript, монорепа, Yarn PnP

- Под **Yarn Berry (PnP)** LSP не видит зависимости без SDK. Один раз в корне репы: `yarn dlx @yarnpkg/sdks vim`
- Для pnpm / node_modules-реп ничего не нужно
- В монорепе открывай nvim **из папки пакета** — tsserver возьмёт меньший `tsconfig` и меньше файлов

### Индексация при каждом запуске?

| движок | что происходит |
|---|---|
| **clangd (C++)** | индекс **на диске** (`.cache/clangd/index/`) → переиспользуется, доиндексируется только изменённое |
| **vtsls (TS)** | индекс **в памяти** → строится заново каждый старт nvim |
| **treesitter** | не индекс: парсит буфер на месте |
| **сам nvim** | ничего не индексирует, стартует моментально |

### Ускорение git на больших репах

На репе с сотнями тысяч файлов `git status` идёт секундами и держит `index.lock` — отсюда «Unable to create index.lock» при stash/discard. Лечится:

```bash
git config core.fsmonitor true && git config core.untrackedCache true
```

Замер на monoNew: **10.9 с → 0.92 с**. Плюс в конфиге lazygit: `git.autoFetch: false`, `git.log.showGraph: when-maximised`.

### Тема под проект

Тема запоминается **на репозиторий** (ключ — корень git, иначе cwd). Выбрал один раз — при следующем открытии этого проекта применится она же.

| клавиши | действие |
|---|---|
| `Space u C` | выбор темы с живым превью, выбранная сохраняется для проекта |
| `Space u B` | прозрачный фон редактора вкл/выкл |

Стор: `~/.local/share/nvim/theme-by-project.json` — обычный JSON, правится руками, удаление строки = откат к дефолту (`tokyonight-moon`).

**Что стоит (тем именно под язык не бывает — подсветка идёт через tree-sitter-группы, они общие; отличается то, под какую палитру тему точили):**

| тема | про что |
|---|---|
| `gruvbox-material` | тёплая, низкий контраст — рабочая лошадка под C/C++ |
| `sonokai` | то же семейство, холоднее и контрастнее |
| `kanagawa`, `everforest`, `melange`, `rose-pine`, `nightfox` | приглушённые, под долгие сессии |
| `night-owl` | писалась под ночной JS/JSX |
| `poimandres` | из мира three.js/react, сине-зелёная приглушённая |
| `vscode` | порт VS Code Dark+ |
| `tokyonight-moon` (дефолт), `cyberdream`, `eldritch`, `synthwave84`, `cyberpunk` | синие/неоновые |

Строка под курсором (`CursorLine`) не берётся из темы, а считается: `Visual`, затемнённый на 55% — поэтому не забивает подсветку синтаксиса ни в одной теме.

### Различение синтаксиса начертанием

Цвет — не единственный канал. `Space u S` включает вторую ось, независимую от палитры:

| начертание | группы |
|---|---|
| обычный | значения и вызовы: `@variable`, `@function`, `@string`, `@number` |
| **жирный** | объявления и структура: `@keyword*`, `@type*`, `@constructor` |
| *курсив* | принадлежность и контекст: параметры, поля, модули, комментарии |
| ***жирный курсив*** | константы времени компиляции: `@constant*`, макросы |

Настройка — `lua/util/syntax-contrast.lua`, таблица `STYLE_BY_GROUP`.

Если жирный плохо отличается от обычного — в `~/.config/ghostty/config` выключи `font-thicken` (он утолщает все глифы и съедает разницу).

# 10. FAQ и траблшутинг

| вопрос / симптом | ответ |
|---|---|
| Как сохранить файл? | `Ctrl+S` или `:w` (сработает автоформат) |
| Как закрыть файл? | `Space b d`; `:q` закрывает **окно**, а не файл |
| Как остановить dev-server? | `Ctrl+/` → `i` → `Ctrl+C` |
| Все ошибки в файле? | `Space x X` |
| Кто менял строку? | `Space g b` |
| Номера строк «скачут» | Относительная нумерация — прицел для `5j`/`12k`; выключить `Space u L` |
| Поиск даёт `0/0`, «Failed to spawn rg» | Нет ripgrep: `brew install ripgrep` |
| `fatal: Unable to create index.lock` | Медленный `git status` держит индекс → включить `core.fsmonitor` (см. часть 7) |
| clangd: `'utils.h' file not found` | Нет `compile_commands.json` в корне CMake-проекта (см. часть 7) |
| TS: «Cannot find module 'react'» | Yarn PnP без SDK → `yarn dlx @yarnpkg/sdks vim` |
| Прозрачность пропала в fullscreen | Входить через `Ctrl+Cmd+F`, не зелёной кнопкой |
| LazyVim: «order of your lazy.nvim imports is incorrect» | Экстры должны быть в `lua/config/lazy.lua` между `lazyvim.plugins` и `{ import = "plugins" }` |
| Крошек (winbar) не видно | Плагин должен грузиться сразу: `lazy = false` |
| lazygit каждый раз сканит заново | Держать его отдельным процессом в панели Ghostty (см. часть 5) |
| Курс по Vim с нуля | `:Tutor` (с большой T) или `vimtutor` |
