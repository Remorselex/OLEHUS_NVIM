# Neovim + LazyVim — шпаргалка

Лидер — `Space`. Нажми `Space` и подожди: `which-key` покажет всё меню.
Эта шпаргалка открывается командой `helpmevim` из любого места.
Забыл клавишу — `Space s k`: поиск сразу по всем хоткеям nvim и по этой шпаргалке, можно по-русски
(«свернуть», «коммит»). `Enter` на хоткее нажимает его, на строке шпаргалки — открывает её на этом месте.

# 2. Основы Vim

### Выживание

| клавиши | действие |
|---|---|
| `i` / `Esc` | вставка / обратно в normal |
| `Ctrl+S` или `:w` | сохранить (работает и из insert) |
| `:wa` · `ZZ` · `:q` · `:qa` | сохранить всё · сохранить+закрыть окно · закрыть окно · выйти |
| `u` / `Ctrl+r` / `.` | отмена / повтор отмены / повторить последнее действие |

### Только клавиатура

- **Мышь и трекпад в nvim ничего не делают**: клики, перетаскивание, прокрутка, тап. Вернуть на время — `Space u M` (и обратно тем же). Скопировать текст мышью мимо nvim — `Shift`+перетаскивание в Ghostty.
- **Плавной прокрутки нет**: прыжки мгновенные, и клавиша, нажатая сразу после прыжка, попадает туда, где курсор на самом деле.
- **Запись макросов выключена**: `q` и `Q` в обычном файле ничего не делают. В окнах, где `q` закрывает (справка, всплывашки, окно VCS), оно закрывает как раньше. Раньше случайные `q` + буква тихо начинали запись (`recording @l` справа внизу), и пока она шла, which-key не показывался — казалось, что `Space` не работает.
- Если клавиши вдруг «не те» и буквы заглавные — проверь Caps Lock: macOS показывает синий значок `⇪` у курсора.

### Правка

| клавиши | действие |
|---|---|
| `dd` `yy` `p` | вырезать строку · копировать · вставить |
| `ciw` `ci(` `ci"` | изменить слово · внутри скобок · внутри кавычек |
| `v` `V` `Ctrl+v` | выделение: символ · строка · блок |
| `Ctrl+v` `3j` `I` текст `Esc` | вставить текст в одну колонку на 4 строках |
| `Ctrl+v` `3j` `$` `A` текст `Esc` | дописать в **конец** каждой строки, без выравнивания пробелами |
| `V` `3j` `:norm A: String,` | то же командой: выполнить `A: String,` на каждой выделенной строке |
| `gl` `ip` `:` · `gl` `ig` `:` | выровнять поля по `:` колонкой (типы в struct, значения в JSON): блок под курсором · весь файл, у каждой структуры своя колонка, курсор остаётся на месте. Дальше `Ctrl+v` по колонке правит их разом. `gl` движение/выделение, потом символ; `=` и прочие — отступ перед ним (`a    = 1`). `:w` вернёт стандартный формат (rustfmt / prettier); `Esc` вместо символа — отмена |
| `>7j` | сдвинуть отступ у 7 строк вниз |

### Автоформат при сохранении

На `:w` срабатывает `clang-format` (C++) / `prettier` (ts/tsx) / `rustfmt` через rust-analyzer (Rust).
Если файл «сам переформатировался» — это оно. Отформатировать прямо сейчас, без сохранения — `Space c f`;
весь Rust-workspace из терминала — `cargo fmt`.
Выключить: `Space u f` (буфер) · `Space u F` (глобально).

Выравнивание колонкой (`byte_mask:    String`, `Small  = 1` в enum) — по проекту. Стандартный rustfmt
его снимает, а нестабильные опции из `rustfmt.toml` stable игнорирует. Зато аргументом командной
строки принимает, поэтому в проекте кладётся `rust-analyzer.toml`:
`rustfmt.extraArgs = ["--config", "struct_field_align_threshold=40,enum_discrim_align_threshold=40,struct_lit_width=19"]`
(`struct_lit_width=19` — чтобы короткие литералы `S { a: 1, b: 2 }` остались в одну строку). Так
сделано в `Mono/Rust`; там же `cargo fmta` — то же из терминала (обычный `cargo fmt` выравнивание снимет).
В остальных проектах формат стандартный. Отдельный кусок можно уберечь от rustfmt: `#[rustfmt::skip]`.

# 3. Навигация

**Правило:** `j`/`k` — только на соседние строки. Дальше — прыжками.

### Мотать по файлу

| клавиши | действие |
|---|---|
| **`Ctrl+D` / `Ctrl+U`** | **полэкрана вниз / вверх** — основной способ |
| `Ctrl+F` / `Ctrl+B` | страница вниз / вверх |
| `gg` / `G` / `42G` | начало · конец файла · к строке 42 |
| `H` / `M` / `L` | верх · середина · низ видимого экрана |
| `zz` / `zt` / `zb` | текущую строку в центр · верх · низ экрана |
| `{` / `}` | предыдущий / следующий блок кода |
| `%` | к парной скобке |
| `[[` / `]]` | к предыдущей / следующей функции |
| `Ctrl+O` / `Ctrl+I` | **назад / вперёд по прыжкам** (Back/Forward как в IDE) |

### Прыжок в любую точку экрана

`s` + 2 символа — подсвечиваются метки, жмёшь метку и ты там (flash.nvim). Быстрее любого скролла.
`S` — выбрать узел кода (treesitter).

### Внутри строки

| клавиши | действие |
|---|---|
| `w` `b` `e` | по словам вперёд · назад · конец слова |
| `0` `^` `$` | начало · первый непробельный · конец строки |
| `f<символ>` / `t<символ>` | к символу / перед символом |
| `;` / `,` | повторить последний `f`/`t` вперёд / назад |

### Относительная нумерация

Слева не абсолютные номера, а **расстояние от курсора** — это прицел:

| клавиши | действие |
|---|---|
| `5j` / `12k` | вниз на 5 / вверх на 12 — число берёшь из колонки |
| `d5j` / `y3k` | удалить 5 строк вниз / скопировать 3 вверх |
| `Space u L` / `Space u l` | вкл-выкл относительную нумерацию / номера вообще |

### Между файлами

| способ | клавиши | когда быстрее |
|---|---|---|
| Fuzzy по имени/пути | `Space Space` | знаешь имя: `bannercard` → Enter; работает и по пути |
| **Navigation bar** (как `Cmd+↑`) | `Space ;` | помнишь *где* лежит: крошки → пивот → меню → стрелки → Enter |
| Дерево файлов | `Space e` | нужен обзор; `/` внутри фильтрует |
| Открытые файлы | `Space ,` | вернуться к буферу |
| Туда-обратно | `Ctrl+^` | метаться между двумя файлами |
| Соседний буфер | `Shift+H` / `Shift+L` | листать по порядку |

### Буферы, окна, вкладки — три разные вещи

- **Буфер** — открытый файл в памяти; полоса сверху = буферы
- **Окно** (split) — вид на буфер; `:q` закрывает **окно**, а не файл
- **Вкладка Vim** — набор окон; это не полоса сверху и не вкладки Ghostty

| клавиши | действие |
|---|---|
| `Space b d` | закрыть буфер (окно остаётся) |
| `Space b o` | закрыть все **остальные** буферы |
| `Space b p` / `Space b P` | закрепить / закрыть незакреплённые |

### Поиск по проекту

| клавиши | действие |
|---|---|
| `Space /` | grep по проекту (живой) |
| `Space s w` | grep слова под курсором |
| `Space s b` | поиск по строкам буфера |
| `Ctrl+q` в пикере | результаты → quickfix, листать `]q` / `[q` |
| `Ctrl+v` / `Ctrl+s` | открыть результат в сплите |

Требует `ripgrep`. Без него пикеры молча дают `0/0` и «Failed to spawn rg».

**Функцию ищут не грепом, а символами:** `Space s S` (по проекту) · `Space s s` (в файле).

# 4. Код: LSP

| клавиши | действие |
|---|---|
| `gd` / `gD` | к определению / к исходному определению (минуя `.d.ts`) |
| `gr` / `gI` | usages / реализации |
| `K` | документация под курсором |
| `Space c a` | quick fix (code action) |
| `Space c r` | rename |
| `Space c f` | форматировать |
| `Space c o` / `c M` / `c u` | TS: organize imports · добавить недостающие · убрать неиспользуемые |

### Ошибки и диагностика

| клавиши | что показывает |
|---|---|
| `Space x X` | все диагностики **текущего файла** |
| `Space x x` | по всему проекту |
| `Space s d` | список с fuzzy-поиском |
| `Space c d` | диагностика под курсором во всплывашке |
| `]d` / `[d` | следующая / предыдущая диагностика |
| `]e` / `[e` | только ошибки · `]w` / `[w` только варнинги |

В окне Trouble: `Enter` перейти · `o` перейти и закрыть · `p` превью · `q` закрыть · `?` справка.

**Rust: ошибки приходят двумя волнами.** Первую rust-analyzer находит сам, по тексту, без сохранения:
несовпадение типов, пропущенные поля, число аргументов. Вторую — ошибки заимствования (moved value,
нет `mut`, `&` и `&mut` одновременно) — даёт только `cargo clippy`, а он запускается на `:w`;
через 1–2 с после сохранения приходят ошибки rustc. Пока есть ошибки типов, rustc до заимствований
не доходит — сначала исправь их. Ошибки в insert-режиме не обновляются нарочно: иначе они мигали бы
на каждом недописанном слове.

### Автокомплит и шаблоны (Rust)

Меню: `Enter` принять · `Ctrl-n` / `Ctrl-p` по списку · `Ctrl-e` закрыть · `Ctrl-Space` открыть вручную.
В раскрытом шаблоне `Tab` / `Shift-Tab` — к следующему / предыдущему полю. Скобки `() [] {}` и
кавычки закрываются сами; `Enter` между `{}` разворачивает блок. Не закрываются, если сразу за
курсором буква, цифра, кавычка, `.`, `$` или `[`, и внутри строки. Выключатель — `Space u p`.

**Свои шаблоны** (`snippets/rust.json`; набери слово и `Enter`):

| набрать | получится |
|---|---|
| `new` | `pub fn new(…) -> Self { Self { … } }` — `Tab` из аргументов в поля |
| `method` / `methodmut` | `pub fn name(&self …)` / `(&mut self …)`, третье поле — ` -> Type` |
| `implfor` | `impl Trait for Type { }`, внутри `fn` даёт методы трейта |
| `tests` | `#[cfg(test)] mod tests { use super::*; #[test] fn … }` |
| `mainr` | `fn main() -> Result<(), Box<dyn Error>>` — чтобы в `main` работал `?` |

Из friendly-snippets: `pfn`, `fn`, `test`, `derive`, `struct`, `match`, `if-let`.

Шаблоны появляются в меню, только когда слово начинается как имя одного из них: иначе нечёткий
поиск с опечатками подсовывал их к новым именам (`History` → `relm-async-factory`), и `Enter`
вставлял целый компонент.

**Что умеет rust-analyzer сам:**

| где | что набрать | что выйдет |
|---|---|---|
| в `impl` | `fn` | `fn …(…) { }` |
| в `impl Display for X {}` | `fn` → `fmt` | полная сигнатура `fmt(&self, f: &mut Formatter<'_>) -> fmt::Result` |
| в выражении | `Self` или имя структуры → пункт `Self {…}` | литерал со **всеми полями** |
| после значения | `.if` `.match` `.ifl` `.lete` `.let` `.ok` `.some` `.dbg` `.ref` `.return` | `value.match` → `match value { … }` со всеми вариантами |

**Действия `Space c a`** (курсор на имени структуры): `Generate new` — конструктор сразу со всеми
полями · `Generate impl` · `Add #[derive]` · `Generate trait impl`. В `impl Trait for X` —
`Implement missing members`; в `match` — `Add missing match arms`; на `Self { }` — `Fill struct fields`.

### Подсказка сигнатуры (окно с документацией над вызовом)

| клавиши | действие |
|---|---|
| `Ctrl+f` / `Ctrl+b` | листать подсказку вниз / вверх на 4 строки, не выходя из ввода. Если открыто меню автодополнения, листается документация выбранного пункта |
| `Ctrl+k` (ввод) / `gK` (обычный режим) | открыть подсказку снова, если закрылась |
| `K` | то же описание целиком в обычном режиме; листается теми же `Ctrl+f` / `Ctrl+b` |

### Сворачивание и комментарии (как в Rider)

| клавиши | действие |
|---|---|
| `za` / клик по стрелке слева | свернуть / развернуть блок под курсором |
| `zc` / `zo` | свернуть / развернуть |
| `zM` / `zR` | свернуть всё / развернуть всё |
| `zj` / `zk` | к следующему / предыдущему сворачиваемому блоку |
| `Space c g` | doc-комментарий по сигнатуре (neogen) |
| `Space u R` | doc-комментарии прозой, как reader mode в Rider — вкл/выкл (по умолчанию выключено) |
| `Space c b` | текст в рамке `╭─╮` (в Visual — выделенные строки) |
| `Space c t` | заголовок-линия `── текст ──────` |
| `Space c B` | линия-разделитель |
| `Space c X` | снять рамку или линию, текст оставить |

Свёрнутый блок показывает первую строку и `⋯ N строк`, свёрнутый doc-комментарий — свою первую фразу. Блоки сворачивания даёт LSP (clangd, vtsls), а где его нет — treesitter, а без обоих — отступы. Doc-комментарий под курсором всегда показан как есть — его можно править. Другие стили рамок: `:CBcatalog`, потом номер: `:CBlabox3`.

### Цвета вложенности

У каждого уровня отступа свой цвет: скобки блока и вертикальная линия внутри него одного цвета,
линия блока под курсором яркая, остальные приглушены. Выключатель — `Space u o`.

Порядок цветов: оранжевый → синий → красно-оранжевый → жёлтый → зелёный → белый, дальше по кругу.
Соседние уровни различаются при любом типе дальтонизма, а яркость скачет через уровень — это
вторая подсказка помимо оттенка. Скобка красится по отступу своей строки, а не по глубине
вложенности: в `.map(|x| {` открыты две скобки, а отступ один, и по глубине цвета ниже такой строки
разошлись бы с линиями. Из-за этого скобки в одной строке (`foo(bar(x))`) все одного цвета — пару
под курсором и так подсвечивает встроенная подсветка парной скобки (прыжок к ней — `%`). Палитра и логика — `lua/util/rainbow-scopes.lua`.

### Markdown как страница

`.md` открывается уже отрисованным: заголовки со значком уровня, таблицы в рамках, блоки кода с подписью языка, списки и чекбоксы. Строка под курсором показана как есть — её можно править. `Space u m` — выключить или включить отрисовку.

# 5. Git

### Окно VCS — `Space g g` (своё, как Commit в IntelliJ)

Отдельная вкладка: слева изменения деревом с галочками и поле сообщения, справа diff выбранного файла. `Space g g` открывает и закрывает её, `q` тоже закрывает. Код — `lua/vcs/`.

**Галочка — это индекс git**: `[x]` файл застейджен целиком, `[~]` частично (часть ханков), `[ ]` нет. Поэтому окно согласовано с gitsigns, Neogit и git в терминале: застейджил ханк где угодно — галочка тут же поменялась.

Статус читается формой, не цветом: буква `M` `A` `D` `R` `?` `!`, удалённый файл зачёркнут, неотслеживаемый курсивом, конфликт жирным.

| клавиша | действие |
|---|---|
| `x` | отметить / снять; в визуальном режиме (`V`) — всё выделенное |
| `X` | отметить или снять все изменения |
| `Enter` | diff файла с фокусом в нём; на папке — свернуть / развернуть; на конфликте — слияние в diffview |
| просто курсор | предпросмотр diff справа |
| `e` | открыть файл в обычной вкладке (F4 в IntelliJ) |
| `l` / `h` | развернуть / свернуть; `h` на файле — к его папке |
| `u` | откатить к HEAD (спросит) |
| `c` | к сообщению коммита |
| `C` · `P` | коммит · коммит и сразу push-диалог |
| `p` | push-диалог: какие коммиты уйдут и куда |
| `L` · `B` | Log · ветки |
| `U` | Update Project: fetch, потом merge или rebase |
| `M` | rebase / merge / cherry-pick остановился: продолжить, пропустить, отменить |
| `W` | worktree: открыть в своей вкладке, создать, удалить |
| `A` | amend — исправить последний коммит (сообщение подставится) |
| `t` | дерево / плоский список |
| `<` · `>` | панель уже · шире (ширина запоминается) |
| `R` · `?` | обновить · клавиши и настройки вида |

В поле сообщения: `Ctrl+K` — коммит, `Ctrl+P` / `Ctrl+N` — свои прошлые сообщения. Черновик переживает перезапуск, во время слияния подставляется `Merge branch …`. Если ничего не отмечено, коммит предложит взять все изменения отслеживаемых файлов.

**Diff справа.** Пока курсор ходит по панели, справа копия только для чтения: LSP не стартует, буферы не копятся. `Enter` в панели или попытка печатать в копии (`i` `a` `o` `Enter`) открывает настоящий файл (`✎` в заголовке) — он правится и сохраняется прямо в diff, метки изменений следуют за правкой. `]c` / `[c` — к соседнему изменению, `Space g h s` / `Space g h r` — застейджить / откатить ханк. Неизменённые куски свёрнуты.

**`?` — клавиши и настройки вида** (и в панели, и в diff). Клавиша меняет вид сразу, меню остаётся открытым:

| в меню | что меняет |
|---|---|
| `1` · `2` | одно окно (старые строки над новыми) · два окна (HEAD \| рабочая копия) |
| `h` | подсветка: вся строка · только полоса слева |
| `w` | игнорировать пробелы |
| `T` | спрятать / показать дерево — diff на всю ширину |
| `<` · `>` | ширина дерева |

Полоса слева читается формой: сплошная `┃` — строка есть только с этой стороны (добавлена справа, удалена слева), пунктир `┇` — строка изменена, `▁` — ниже удалены строки. Изменённые слова в одном окне: удалённые зачёркнуты, добавленные подчёркнуты. Настройки вида хранятся в `~/.local/state/nvim/vcs.json`.

Упал хук или push — полный вывод в окне снизу.

`Space g G` — lazygit, запасной.

### Log — `Space g l` (как Log в IntelliJ)

Своя вкладка: сверху коммиты с графом веток, снизу слева файлы выбранного коммита и его сообщение, справа diff файла (обе стороны только для чтения, вид — тот же `?`: одно окно / два). При выборе коммита сразу показан diff первого файла. По умолчанию — история текущей ветки; длинная история подгружается сама, когда курсор подходит к концу.

Метки читаются формой: `[ветка]` — локальная, `(origin/ветка)` — удалённая, `(origin)` — удалённая с тем же именем, `<тег>`; ветка, на которой ты стоишь, перевёрнута. `●` — коммит, `◆` — merge.

| клавиша | действие |
|---|---|
| `j` `k` | следующий / предыдущий коммит (строки графа пропускаются) |
| `Enter` `l` `Tab` | к файлам коммита; в файлах `Enter` — в diff, `e` — открыть файл, `h` — назад |
| `Tab` / `S-Tab` в diff | к коммитам / к файлам |
| `/` · `a` · `b` | фильтр: текст сообщения · автор (я / любой / вписать) · ветка (текущая / все / любая) |
| `f` · `d` · `F` | фильтр: путь · дата · снять все фильтры |
| `y` | скопировать хеш |
| `c` | cherry-pick; `V` + `c` — несколько коммитов по порядку |
| `v` | revert: новый коммит отменяет этот |
| `n` · `t` | новая ветка здесь (и переключиться) · тег здесь |
| `X` | reset текущей ветки сюда: soft / mixed / hard (hard спросит ещё раз) |
| `o` | checkout этого коммита (detached HEAD, спросит) |
| `B` · `U` · `p` · `M` · `W` | ветки · Update Project · push-диалог · продолжить или отменить операцию · worktree |
| `R` · `q` · `?` | перечитать · закрыть · клавиши и вид |

**История файла — `Space g f`**: тот же Log с фильтром по текущему файлу, через переименования (`--follow`); при каждом коммите справа сразу diff этого файла. **История строк — выдели строки `V` и `Space g f`**: только коммиты, которые меняли эти строки (`git log -L`).

### Ветки — `Space g c` (или `B` в окне VCS и в Log)

Всплывающее окно: Recent (куда переключался последнее время), Local, Remote по удалённым репозиториям. У локальной ветки — `↑2 ↓1` относительно upstream, `gone`, если upstream удалили, и сам upstream. Текущая отмечена `●`. Remote с больше чем 15 ветками свёрнут (`Enter` / `l` — развернуть, `h` — свернуть). `j` `k` ходят только по веткам.

| клавиша | действие |
|---|---|
| `Enter` | checkout; локальные изменения мешают — предложит спрятать их, переключиться и вернуть (smart checkout); на удалённой ветке создаст локальную с отслеживанием |
| `n` | новая ветка от выбранной |
| `m` · `r` | merge выбранной в текущую · rebase текущей на выбранную (спрашивают) |
| `R` · `d` | переименовать · удалить (неслитую — спросит второй раз; удалённую — `push --delete`) |
| `c` · `C` | сравнить: что есть в выбранной и нет в текущей · наоборот — открывается в Log |
| `l` · `p` · `u` | Log ветки · push-диалог ветки · обновить ветку из upstream (текущую — Update Project, другую — fast-forward без checkout) |
| `w` | открыть ветку в worktree: есть — перейти, нет — создать рядом с основным деревом |
| `f` · `/` · `Backspace` | fetch всех remote · фильтр по имени · снять фильтр |

### Push-диалог — `p` (и `P` после коммита)

Показывает, куда уйдёт ветка (`main → origin/main`, или `(new branch)` — тогда upstream заведётся сам), и коммиты, которые уйдут. Если на remote есть коммиты, которых нет у тебя, предупреждает: push отклонят, сначала `U`. `Enter` — push, `F` — `--force-with-lease` (спросит), `t` — вместе с тегами. Ссылку на MR, которую присылает GitLab, показывает в уведомлении.

### Update Project — `Space g u` (или `U`)

`fetch --all --prune`, потом подтягивает текущую ветку из upstream: merge или rebase — как `git pull` по `pull.rebase` (у тебя `false`, значит merge), а в меню `?` клавиша `u` переключает. Локальные изменения убираются на время и возвращаются (`--autostash`). В уведомлении — сколько коммитов и файлов пришло.

### Операция остановилась на конфликте — `M`

Rebase, merge, cherry-pick или revert встали на конфликте — в шапке окна VCS перевёрнутая метка вроде `REBASING 1/2 · M` (во время rebase там имя ветки, а не detached-хеш), конфликтные файлы — в группе Merge Conflicts. Разрешил, отметил `x` — `M` → Continue; ещё есть Skip (пропустить коммит) и Abort (вернуть как было, спросит). Сообщение коммита, которое приготовил git, само появляется в поле и уходит, когда операция закончена.

### Постоянная панель (главная схема, аналог Git в IDEA)

lazygit — внешний процесс: если он дочерний для nvim, закрытие окна убивает его и следующий запуск сканит всё заново. Поэтому держим его **отдельным долгоживущим процессом**:

1. редактор запускать через `v` (слушает сокет `/tmp/nvim.sock`):

```bash
v .
```

2. сплит под git — `Cmd+D` (вправо) или `Cmd+Shift+D` (вниз), в нём:

```bash
lg
```

3. переключение панелей — `Cmd+Alt+←/→`, процессы не трогаются
4. в lazygit `e` на файле → файл открывается **в соседнем nvim**, lazygit сохраняет состояние

`Space g G` — lazygit внутри nvim для разовых заглядываний (`Space g g` теперь окно VCS).

### Патчи

Из шелла больше не нужно. Две разные вещи:

**Патч как операция** — собрать из произвольных строк любых коммитов и переложить. Это lazygit, `Ctrl+P` на выделенных строках в файле коммита:

| | |
|---|---|
| `c` | сбросить собранный патч |
| `a` | применить |
| `r` | применить в обратную сторону |
| `y` | скопировать патч в буфер обмена |

Набор пунктов зависит от контекста: на коммите не-HEAD добавляются перенос патча в другой коммит и в индекс.

**Патч как файл** — `format-patch` / `am`; в Neogit это не портировали, поэтому сделано своим модулем `lua/util/git-patch.lua`. Файлы кладутся в `~/patches/`, путь сразу попадает в буфер обмена.

| клавиши | что |
|---|---|
| `Space g m w` | все незакоммиченные изменения → патч |
| `Space g m s` | только застейдженное → патч |
| `Space g m f` | текущий файл → патч |
| `Space g m c` | выбрать коммит → `format-patch -1` (формат для `git am`) |
| `Space g m a` | выбрать файл из `~/patches` и применить |

Применение идёт через `git apply --check`: если патч не ложится, рабочее дерево не трогается вообще.

### Worktree: ветки не переключают, а ходят по каталогам

Главное правило git: **одна ветка может быть выкинута только в одном worktree**. Поэтому «не могу прыгнуть на master» — это не баг lazygit, а инвариант git:

```
fatal: 'master' is already used by worktree at '/Users/user/IdeaProjects/monoNew-wktr2'
```

master уже открыт в соседнем каталоге. В worktree-модели на него не переключаются — в него **переходят**.

| команда | что делает |
|---|---|
| `wt` | fzf-список всех worktree → переход в выбранный |
| `wt master` | переход в worktree, чей путь или ветка содержит подстроку |
| `wt-add <ветка>` | создать worktree рядом с основным деревом, каталог назвать по ветке |
| `wt-rm` | выбрать worktree и удалить |
| `git worktree list` | плоский список: путь → ветка |

В промпте линкованный worktree помечается **`wt:<имя>`** перед веткой (в основном дереве метки нет) — видно, где ты, без единой команды.

Каталоги называй по ветке (`monoNew-master`), а не `wktr2` — через неделю не вспомнить, что где.

**В nvim — `Space g w`** (или `W` в окне VCS и в Log): окно со всеми worktree — ветка, `↑↓` к upstream, сколько изменений (`clean` / `3 changed`), путь; `main`, `locked`, `missing` (каталог пропал). Текущий отмечен `●`.

| клавиша | действие |
|---|---|
| `Enter` | **перейти**: worktree открывается в своей вкладке nvim с локальным каталогом (`:tcd`) — поиск файлов, проводник и `Space g g` в ней работают с этим worktree, остальные вкладки остаются где были. Вкладка уже есть — переход в неё |
| `n` | новый worktree, как `wt-add`: новая ветка от текущей или свободная ветка (локальная, удалённая — заведётся отслеживающая); каталог предложит рядом с основным деревом по имени ветки (`monoNew-feature-login`), его можно поправить. После создания — сразу переход |
| `d` | удалить, как `wt-rm`: каталог уходит, ветка остаётся; есть незакоммиченное — спросит второй раз. Вкладки этого worktree закрываются, его неизменённые буферы — тоже |
| `g` · `l` | окно VCS · Log этого worktree |
| `L` · `p` · `y` | lock / unlock (prune его не тронет) · prune (убрать записи о пропавших каталогах) · скопировать путь |

В окне VCS linked worktree подписан **`wt:<имя>`** перед веткой — как в промпте.

**Окно веток знает про worktree**: ветка, выкинутая в другом worktree, помечена `wt:<имя>`, и `Enter` на ней (или на её удалённой) вместо ошибки git «already used by worktree» предлагает перейти туда. `w` на любой ветке — открыть её в worktree: есть — перейти, нет — создать.

В lazygit worktree живут вкладкой в панели файлов: `1`, затем `]` / `[` для переключения вкладок, `w` — создать новый. Остальные клавиши панели — по `?`.
В Neogit — попап `w`.

### difftastic — структурный дифф

Сравнивает деревья разбора, а не строки: переносы, переформатирование и переезд кода не показываются как изменение.

```
git diff  →  4 insertions(+), 1 deletion(-)
git dft   →  No syntactic changes.
```

| команда | что |
|---|---|
| `git dft [путь]` | структурный дифф рабочей копии или коммита |
| `git dlog` | лог с структурными диффами |
| `git dshow <коммит>` | показать коммит структурно |

Дефолтный `git diff` не тронут — delta остаётся везде, включая lazygit и diffview. difftastic вызывается только этими тремя алиасами: структурный дифф медленнее и не умеет в подсветку слов внутри строки, так что как ежедневный он хуже.

### Neogit — порт Magit (самый близкий аналог VCS в IDEA)

`Space g n` — буфер статуса, из него делается всё. Это обычный буфер nvim: навигация как в коде, `q` закрывает, состояние не теряется.

| в статусе | действие |
|---|---|
| `<tab>` | свернуть/развернуть секцию, `1`…`4` — глубина всего дерева |
| `<cr>` | **открыть файл на правку прямо отсюда**, `<s-cr>` — подглядеть |
| `s` / `u` | застейджить / снять — файл, ханк или выделенные строки |
| `x` | откатить изменение (файл/ханк/строки) |
| `-` | инвертировать ханк |
| `<c-v>` `<c-x>` `<c-t>` | открыть файл в вертикали / горизонтали / вкладке |

Дальше — попапы: жмёшь букву, видишь меню с флагами, выбираешь. Флаги залипают между вызовами.

| клавиша | попап | что внутри |
|---|---|---|
| `c` | Commit | `c` коммит, `a` amend, `w` reword, `f` fixup, `s` squash, `F`/`S` мгновенные fixup/squash, **`x` absorb** |
| `l` | Log | по текущей ветке, HEAD, всем веткам, всем рефам, с фильтрами |
| `A` | Cherry-pick | `A` pick, `a` apply (без коммита), `h` harvest, `m` squash, `d` donate, `n` spinout, `s` spinoff |
| `v` | Revert | откатить конкретный коммит коммитом-обраткой |
| `r` | Rebase | `i` интерактивно, **`m` изменить коммит в истории**, **`w` переписать сообщение**, **`d` удалить коммит**, `f` autosquash, `s` подмножество |
| `X` | Reset | `f` файл, `b` ветка, `s` soft, `m` mixed, `h` hard, `k` keep, `i` только индекс, `w` только рабочая копия |
| `Z` | Stash | `z` всё, `i` только индекс, `w` только рабочая копия, `x` с сохранением индекса, `p`/`a`/`d` pop/apply/drop |
| `d` | Diff | открывается в diffview |
| `b` `t` `m` `p` `P` `f` `M` `w` `B` `i` | branch, tag, merge, pull, push, fetch, remote, worktree, bisect, ignore |
| `?` | справка по всем клавишам текущего буфера |

`Space g N` — сразу лог коммитов. На коммите в логе те же попапы: `A` черипикнуть его, `v` реверт, `X f` откатить один файл к его состоянию.

**Сообщение коммита пишется в обычном буфере** — со спеллчеком, undo, LSP и твоими биндами. `:wq` коммитит, `:q!` отменяет.

`c x` (absorb) — раскидывает текущие правки fixup-коммитами по тем коммитам, которые эти строки ввели, и автоматически делает autosquash. Требует бинарь `git-absorb` (стоит).

### lazygit: базовые клавиши

| клавиша | действие |
|---|---|
| `space` / `a` | стейдж файла / всех |
| `Enter` на файле | вид по кускам (hunk): `space` стейдж, `d` выбросить, `v` диапазон |
| `c` | коммит · `A` влить застейдженное в выбранный коммит |
| `b` | ветки · `f` fetch · `s` stash |
| `+` | развернуть панель на весь экран |
| `z` | **undo** последней операции (через reflog) |
| `?` | справка по текущей панели |

### Ребейз, черипик, конфликты

| клавиша | действие |
|---|---|
| `e` в логе | начать интерактивный ребейз с коммита |
| `s` / `f` / `r` / `d` | squash · fixup · reword · drop |
| `Ctrl+J` / `Ctrl+K` | переставить коммит вниз / вверх |
| `Shift+C` / `Shift+V` | скопировать коммит(ы) / применить (cherry-pick) |
| конфликт | зайти в файл → выбрать сторону, `e` — открыть в nvim; `c` continue, `a` abort |

### Откат файла

| задача | как |
|---|---|
| выбросить все правки файла | Files → `d` → «discard all changes» |
| выбросить только незастейдженное | Files → `d` → «discard unstaged» |
| откатить один кусок | `Enter` на файле → hunk → `d` |
| вернуть файл из старого коммита | Commits → коммит → `Enter` → файл → `c` |
| меню ресетов (hard/soft/upstream) | `D` |

⚠️ Discard незакоммиченного **необратим** — reflog не спасёт. Сомневаешься → сначала `s` (stash).

### Стеш и патчи (lazygit)

**Стешнуть один файл** (прямой команды нет — через стейдж):
1. `space` на нужном файле в Files (застейджить только его)
2. `S` → «stash staged changes»

Так же работает для части файла: `Enter` → `space` на кусках → `S`.

| клавиша | действие |
|---|---|
| `s` | стешнуть всё |
| `S` | меню: all / staged / unstaged / keep index |
| `g` / `r` в панели Stash | вернуть (pop) / переименовать |

Из шелла: `git stash push -- path/to/file`

**Custom patch** (`Ctrl+P`) — перенос изменений между коммитами:
Commits → `Enter` на коммите → `space` на файле (весь) или `Enter`+`space` на кусках (часть) → `Ctrl+P` → apply / move to commit / remove from commit / pull out into new commit / copy to clipboard.

**Патч-файлом для отправки** — быстрее из шелла:

| задача | команда |
|---|---|
| один файл | `git diff -- path > one.patch` |
| всё незастейдженное | `git diff > all.patch` |
| всё вместе со стейджем | `git diff HEAD > all.patch` |
| только стейдж | `git diff --cached > staged.patch` |
| коммит | `git format-patch -1 <sha>` |
| применить | `git apply all.patch` |

В lazygit `Ctrl+O` копирует дифф в буфер, `y` в Files — путь файла.

### Диффы

Настроен **delta**: подсветка синтаксиса + пословная зелёно-красная подсветка внутри строки (в lazygit и в `git diff`/`show`/`log -p`).

| где | как |
|---|---|
| `n` / `N` в диффе | прыжки между изменёнными участками |
| `Space g v d` | diffview: полноэкранный дифф + дерево изменённых файлов |
| `Space g v f` / `g v r` | история файла / история репы |
| конфликт в diffview | три панели: ours / theirs / результат |

### Инлайн в буфере (gitsigns)

| клавиши | действие |
|---|---|
| `]h` / `[h` | следующий / предыдущий изменённый кусок |
| `Space g h s` / `g h p` / `g h r` | застейджить кусок · превью «как было» · откатить кусок |
| `Space g v h` / `g v w` / `g v x` | подсветка изменённых строк · пословная · показать удалённые |

### Blame

| клавиши | что |
|---|---|
| `Space g b` | автор, дата, коммит для строки под курсором |
| `Space g v b` | постоянная inline-аннотация (как Annotate в IDEA) |
| `:Gitsigns blame` | панель blame для всего файла |

### Переключение окон и фокус

| клавиши | действие |
|---|---|
| `Ctrl+H` / `J` / `K` / `L` | перейти в окно влево / вниз / вверх / вправо |
| **`Ctrl+W` `w`** | цикл по **всем** окнам, включая плавающие — спасалка, когда фокус «потерялся» |
| `Ctrl+W` `p` | вернуться в предыдущее окно |
| `Ctrl+W` `o` | закрыть все окна, кроме текущего |
| `Space w d` | закрыть текущее окно |

Плавающие окна живут отдельно — `Ctrl+H/L` из них не работает, у каждого своя клавиша выхода:

| окно | как вернуть фокус |
|---|---|
| терминал (`Ctrl+/`) | `Ctrl+/` — спрятать (тот же хоткей) |
| окно VCS (`Space g g`) | `q` или снова `Space g g` |
| lazygit (`Space g G`) | `q` |
| пикер (`Space Space`, `Space /`) | `Esc` закрыть · `/` фокус ввод↔список · `Alt+W` цикл ввод→список→превью |
| Explorer (`Space e`) | `Ctrl+L` уйти в редактор · `Space e` свернуть |
| диагностика (`Space x X`) | `q` |

Мышь не нужна никогда: всплывашка закрывается своей клавишей, между обычными окнами — `Ctrl+H/J/K/L`, а `Ctrl+W w` вытащит из любого состояния.

# 6. Терминал и запуск

### Терминал

| клавиши | действие |
|---|---|
| `Ctrl+/` | открыть / свернуть плавающий терминал (процесс продолжает работать) |
| `i` / `a` | войти в terminal mode (печатать) |
| `Ctrl+C` | **остановить** процесс (dev-server) |
| `Esc` `Esc` **быстро** | выйти в normal mode (окно **200 мс**! медленный двойной Esc уходит в процесс) |
| `q` | спрятать окно — только из normal mode |
| `exit` / `Ctrl+D` | закрыть терминал совсем |

`Ctrl+/` только **прячет** терминал — dev-server продолжает крутиться. Остановить — сначала `Ctrl+C` внутри.

Самый надёжный способ закрыть: **`Ctrl+/`** — работает прямо из terminal mode (тот же хоткей и открывает, и прячет). `q` и `Esc` в terminal mode уходят процессу, а не nvim.

### npm-скрипты (кнопка ▶)

| клавиши / команда | что |
|---|---|
| `Space r r` | список скриптов **пакета под курсором** → Enter |
| `Space r l` | повторить последний скрипт |
| `nr` / `nr -` | то же из шелла (сам определяет npm/yarn/pnpm по локфайлу) |
| `ni` / `ni <pkg>` / `nlx <pkg>` | install · добавить пакет · разовый запуск (как npx) |

### Сборка C++ и дебаг

```bash
cmake -S . -B build -G Ninja -DCMAKE_EXPORT_COMPILE_COMMANDS=ON && cmake --build build
```

| клавиши | действие |
|---|---|
| `Space d B` | breakpoint |
| `Space d c` / `d o` / `d i` | запустить/продолжить · step over · step into |
| `Space d u` | панель дебага (переменные, стек) |

### Rust: сборка, запуск, тесты

Те же клавиши, что для C++, — по типу открытого файла. Команда выполняется из корня workspace для пакета, к которому относится файл, в плавающем терминале.

| клавиши | действие |
|---|---|
| `Space r c` | `cargo run -p <пакет>` (из `src/bin/x.rs` — `--bin x`, из `examples/` — `--example`) |
| `Space r b` | `cargo build -p <пакет>` |
| `Space r t` | `cargo test -p <пакет>`, из файла в `tests/` — только этот файл |
| `Space r o` | снова показать вывод последнего запуска (спрятанный `q`) / спрятать |
| `Space c R` | действия rust-analyzer (rustaceanvim) |
| `Space d r` | отладка: выбрать, что запустить под codelldb |

Окно вывода (так же и у C++): пока программа работает, клавиши уходят в неё; дойти до вывода — `Esc` `Esc`. Когда программа завершилась (`[Process exited 0]`), окно уже в обычном режиме: `k`/`Ctrl+u`/`gg` листают, `/` ищет, `y` копирует, `:w ~/run.txt` сохраняет весь вывод в файл, `q` прячет. Хранится 100 000 последних строк.

Языковой сервер — `rust-analyzer` из rustup: `rustup component add rust-analyzer`.

# 7. Окружение проектов

### C++ — без этого clangd слепой

clangd понимает проект только через `compile_commands.json`:

```bash
cmake -S . -B build -DCMAKE_EXPORT_COMPILE_COMMANDS=ON && ln -sf build/compile_commands.json .
```

В CLion-проектах база уже есть в `cmake-build-debug/` — достаточно симлинка в корень CMake-проекта, CLion её сам обновляет при reload.

### TypeScript, монорепа, Yarn PnP

- Под **Yarn Berry (PnP)** LSP не видит зависимости без SDK. Один раз в корне репы: `yarn dlx @yarnpkg/sdks vim`
- Для pnpm / node_modules-реп ничего не нужно
- В монорепе открывай nvim **из папки пакета** — tsserver возьмёт меньший `tsconfig` и меньше файлов
- «The JS/TS language service crashed 5 times» — tsserver упирался в кучу 3 ГБ и падал по кругу (`SIGABRT` в `~/.local/state/nvim/lsp.log`). Поднято до 16 ГБ в `plugins/typescript-memory.lua`; если повторится — посмотреть, сколько он ест на самом деле: `ps -axo rss,command | grep tsserver`

### Индексация при каждом запуске?

| движок | что происходит |
|---|---|
| **clangd (C++)** | индекс **на диске** (`.cache/clangd/index/`) → переиспользуется, доиндексируется только изменённое |
| **vtsls (TS)** | индекс **в памяти** → строится заново каждый старт nvim |
| **treesitter** | не индекс: парсит буфер на месте |
| **сам nvim** | ничего не индексирует, стартует моментально |

### Ускорение git на больших репах

На репе с сотнями тысяч файлов `git status` идёт секундами и держит `index.lock` — отсюда «Unable to create index.lock» при stash/discard. Лечится:

```bash
git config core.fsmonitor true && git config core.untrackedCache true
```

Замер на monoNew: **10.9 с → 0.92 с**. Плюс в конфиге lazygit: `git.autoFetch: false`, `git.log.showGraph: when-maximised`.

### Тема под проект

Тема запоминается **на репозиторий** (ключ — корень git, иначе cwd). Выбрал один раз — при следующем открытии этого проекта применится она же.

| клавиши | действие |
|---|---|
| `Space u C` | выбор темы с живым превью, выбранная сохраняется для проекта |
| `Space u B` | прозрачный фон редактора вкл/выкл |

Стор: `~/.local/share/nvim/theme-by-project.json` — обычный JSON, правится руками, удаление строки = откат к дефолту (`tokyonight-moon`).

**Что стоит (тем именно под язык не бывает — подсветка идёт через tree-sitter-группы, они общие; отличается то, под какую палитру тему точили):**

| тема | про что |
|---|---|
| `gruvbox-material` | тёплая, низкий контраст — рабочая лошадка под C/C++ |
| `sonokai` | то же семейство, холоднее и контрастнее |
| `kanagawa`, `everforest`, `melange`, `rose-pine`, `nightfox` | приглушённые, под долгие сессии |
| `night-owl` | писалась под ночной JS/JSX |
| `poimandres` | из мира three.js/react, сине-зелёная приглушённая |
| `vscode` | порт VS Code Dark+ |
| `tokyonight-moon` (дефолт), `cyberdream`, `eldritch`, `synthwave84`, `cyberpunk` | синие/неоновые |

Строка под курсором (`CursorLine`) не берётся из темы, а считается: `Visual`, затемнённый на 55% — поэтому не забивает подсветку синтаксиса ни в одной теме.

### Различение синтаксиса начертанием

Цвет — не единственный канал. `Space u S` включает вторую ось, независимую от палитры:

| начертание | группы |
|---|---|
| обычный | значения и вызовы: `@variable`, `@function`, `@string`, `@number` |
| **жирный** | объявления и структура: `@keyword*`, `@type*`, `@constructor` |
| *курсив* | принадлежность и контекст: параметры, поля, модули, комментарии |
| ***жирный курсив*** | константы времени компиляции: `@constant*`, макросы |

Настройка — `lua/util/syntax-contrast.lua`, таблица `STYLE_BY_GROUP`.

Если жирный плохо отличается от обычного — в `~/.config/ghostty/config` выключи `font-thicken` (он утолщает все глифы и съедает разницу).

# 10. FAQ и траблшутинг

| вопрос / симптом | ответ |
|---|---|
| Как сохранить файл? | `Ctrl+S` или `:w` (сработает автоформат) |
| Как закрыть файл? | `Space b d`; `:q` закрывает **окно**, а не файл |
| Как остановить dev-server? | `Ctrl+/` → `i` → `Ctrl+C` |
| Все ошибки в файле? | `Space x X` |
| Кто менял строку? | `Space g b` |
| Номера строк «скачут» | Относительная нумерация — прицел для `5j`/`12k`; выключить `Space u L` |
| Поиск даёт `0/0`, «Failed to spawn rg» | Нет ripgrep: `brew install ripgrep` |
| `fatal: Unable to create index.lock` | Медленный `git status` держит индекс → включить `core.fsmonitor` (см. часть 7) |
| clangd: `'utils.h' file not found` | Нет `compile_commands.json` в корне CMake-проекта (см. часть 7) |
| nvim занял полокна: статусная строка посередине, ниже пусто | Командная строка (`cmdheight`) отъела строки: уменьшение единственного окна (`Ctrl+↓`, `Ctrl-W -`) отдаёт их ей. Чинится само, всплывёт уведомление с последними клавишами; вручную — `:set ch=0` |
| Два explorer рядом | Был повторный `Space e`, пока первый ещё открывался (snacks не видит его до следующего такта). Теперь повтор в этот момент игнорируется (`util/explorer.lua`); лишний закрыть — `q` в нём |
| Вывод `Space r c` пропал, когда начал листать | Раньше окно после конца программы оставалось в режиме терминала, а там первая же клавиша удаляет буфер вместе с выводом. Теперь после `[Process exited N]` окно само переходит в обычный режим (`util/run-terminal.lua`); спрятанное `q` окно возвращает `Space r o` |
| TS: «Cannot find module 'react'» | Yarn PnP без SDK → `yarn dlx @yarnpkg/sdks vim` |
| Прозрачность пропала в fullscreen | Входить через `Ctrl+Cmd+F`, не зелёной кнопкой |
| LazyVim: «order of your lazy.nvim imports is incorrect» | Экстры должны быть в `lua/config/lazy.lua` между `lazyvim.plugins` и `{ import = "plugins" }` |
| Крошек (winbar) не видно | Плагин должен грузиться сразу: `lazy = false` |
| lazygit каждый раз сканит заново | Держать его отдельным процессом в панели Ghostty (см. часть 5) |
| Курс по Vim с нуля | `:Tutor` (с большой T) или `vimtutor` |
